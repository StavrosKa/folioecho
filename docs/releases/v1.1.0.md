# FolioEcho v1.1.0

Independent bookshops can turn their existing catalogue into evidence-backed
cultural event ideas, then shape an editable evening programme.

**Live demo:** https://folioecho.netlify.app/

## Included

- Public Netlify demo with isolated visitor workspaces and persistent Postgres data.
- Real Qloo book resolution, music/movie affinities, explainable scoring and
  what-if repair against fixed normalization references.
- Overview landing screen; sidebar badges show total copies and selected hidden gems.
- Excel (.xlsx), CSV and JSON import with automatic conversion, row validation,
  a prominent gold import control and a practical guide with a CSV template.
- Editable event drafts, per-draft Delete and Undo, and detailed evening programmes.
- Bookshop profile photo upload up to 2 MiB and on-demand branded PDF exports.
- Optional OpenAI host-sponsored demo or encrypted temporary personal keys,
  separate daily allowances, measured tokens and estimated application costs.
- Docker package: `ghcr.io/stavroska/folioecho:1.1.0` (also tagged `latest`).

## Validation and limits

The release workflow runs type checks, 38 regression tests, Node and Netlify builds,
and a container storage smoke test before publishing the package and this release.
Live Qloo planning, repair, persistence and visitor isolation have been verified on
the public demo. OpenAI model execution still requires a real operator/user key;
no successful live OpenAI output or billing verification is claimed.

The live Qloo pilot processes up to 25 catalogue titles per run. Some original
discovery screens retain labelled demonstration content. Personal-key cost figures
are estimates of FolioEcho activity, not an OpenAI invoice or account balance.

No API keys, local databases, uploaded profile photos, raw private API responses,
exports or local configuration files are included in the source or container.

The container uses the local single-workspace Node/SQLite mode. Bind its published
port to loopback and configure provider keys only at runtime. The public hosted
multi-visitor app uses the separate Netlify deployment target.

GitHub may initially make a new container package private. If so, the repository
owner must set the package visibility to Public in its Package settings before
anonymous pulls work.
